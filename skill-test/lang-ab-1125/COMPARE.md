# 한국어 vs 영문 SKILL.md 비교 (2026-11-25)

- 시연: `demo-1127-mes`에서 무작위로 고른 S2-yield. 두 실행의 프롬프트는 같은 한국어이고, 다른 것은 읽은 SKILL.md(scratchpad의 `skill-ko` / `skill-en`)뿐이다. 모델은 둘 다 Sonnet, 각 1회.
- SKILL.md 토큰은 Haiku 에이전트가 파일을 한 번 읽을 때 늘어난 토큰으로 쟀다(5,000단어 파일로 보정):
  - 원본 약 18k
  - 한국어(1~3번 반영) 약 10.3k
  - 영문 약 7.9k

| 항목 | 한국어 | 영문 |
|---|---|---|
| verify 결과 | 점검 0건, 경고 0, 오류 0 | 점검 0건, 경고 0, 오류 0 |
| 도구 호출 / 시간 | 24회 / 6분 05초 | 15회 / 5분 07초 |
| 보고 언어 | 한국어 | 한국어 |
| 경계값 행 | T05 95.0 % 합격 | T02 95.0 % 통과 |
| 판정판 | 하나, 크게 | 하나, 크게 |
| 수율 카드 | 큰 값(카드 높이 충분) | 카드가 낮아 값 글자가 작다 |
| 주 동작 버튼 | 판정판 옆 칸(스캔칸과 함께) | 구획 제목 줄 오른쪽 |
| Release 막기 | 확정 비활성 + 알람색 띠 + Save에서 재확인 | 확정 비활성 + 띠 + "원인 확인 완료" 버튼 |

| 지침상 막힌 점 | `verify.sh` exe 상대 경로(수정함), Titled 높이, 행 수 다른 표 나란히 | Titled 높이, 행 수 다른 표 나란히, dialog 비활성 이유 자리 |

결론(1회씩이라 경향만 본다)
- 영문 지침으로도 한국어 프롬프트를 똑같이 따랐다. 화면 문구, 보고, 4-1 기준(경계값, 소수 자리, 상태색, 판정판 하나, StatusText 굵게)이 모두 지켜졌다.
- 품질 차이는 언어 때문이라기보다 실행마다 생기는 편차로 보인다. 영문 쪽은 카드 높이가 낮았고, 한국어 쪽은 모니터링 화면에 스캔칸을 넣었다.
- 두 실행 모두 같은 지침 빈틈을 지적했다: `Titled` 제목 높이, 행 수가 다른 정해진 표 두 개를 나란히 두는 방법.

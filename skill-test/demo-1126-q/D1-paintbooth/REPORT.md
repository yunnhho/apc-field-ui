## 에이전트 보고 원문

**1) 만든 화면·dialog와 PNG**
- 메인 화면 `MainView` — `out\MainForm.png`. 위→아래: 판정판, 부스 타일 5개, 투입 정보 띠, 선택 부스 현재값 카드 4개, 8시간 온도·습도 추이, 환경 이탈 이력(13행). 이력 제목줄에 `조치 등록` 버튼.
- 이탈 조치 등록 dialog `ActionDialog` — `out\ActionDialog.png`. 막힌 상태(진행 중 이탈 + "영향 없음" 선택)로 render.
- 판정 로직은 `Data/Models.cs`의 `ItemSpec.Judge` 한 곳. 경계 비율 10%, 정지 권고 180초 상수.

**2) 검증 결과**
- render 점검 0건(MainForm, ActionDialog). 빌드 경고 0, 오류 0. exe 실행 안 함.

**3) UX 결정**
- 판정판: "클리어 습도 이탈 · 라인 투입 정지 권고" / "상한 초과 78 %RH (상한 75) · 00:04:20 지속". 3분 미만이면 정지 권고 문구 없음. 이탈 없으면 정상/주의 요약.
- 타일은 이름과 램프만. 누르면 카드·추이가 그 부스로 바뀜. 처음 선택은 이탈 중인 부스(클리어).
- 카드는 관리 범위와 판정을 글로("관리 범위 55 ~ 75 · 이탈"). 오븐 습도·풍속·차압은 "관리 안 함". 정지 부스(프라이머)는 판정 없이 Stop.
- 이력 "영향 행거" 열은 모든 행 굵게, 조치 없는 건은 빨간색. 행거 번호는 이탈 시작·종료 시각에서 계산. 진행 중인 건은 "H-1352 ~ H-1355 · 투입 중".
- 조치 등록 버튼은 선택 행 없음·이미 조치됨이면 꺼지고 이유를 버튼 왼쪽에 글로.
- dialog: 부스·항목·구간·영향 행거·확인자 읽기 전용. 진행 중 이탈에서 "영향 없음"이면 등록 버튼 꺼짐 + "이탈 진행 중 · 영향 없음으로 닫을 수 없음".

**4) 정한 기준값 (확인 질문)**
1. 전처리·프라이머 관리 범위를 베이스·클리어와 같게 했다(21.0~25.0, 55~75, 0.30~0.50, +5~+15). 부스별 범위가 따로 있나?
2. 주의 기준은 관리 폭의 10%, 경계 포함. 온도 24.6 이상·21.4 이하, 습도 73 이상·57 이하, 풍속 0.48 이상·0.32 이하, 차압 14 이상·6 이하, 오븐 144 이상·136 이하. 경계값이 맞나? 샘플 베이스 온도 25.0은 상한과 같아 주의.
3. 판정은 표시 자릿수로 반올림한 값으로 비교한다.
4. 판정판은 부스 선택과 무관하게 라인 전체의 진행 중 이탈을 말한다. 선택 부스 기준으로 할까?
5. 정지 부스(프라이머)는 값을 판정하지 않고 타일·카드를 Stop으로 한다. 정지 부스에서 이탈 기록을 남기는 경우가 있나?
6. 행거 번호 H-NNNN, 06:00부터 1.5분마다 1씩 증가로 가정. 도료 Lot(PL-261124-07)·색상 코드(NH-731P) 형식도 정함. 실제 번호 체계는?
7. 이력 "최대값" 열 머리글을 "최대 이탈값"으로 바꿨다. 하한 미달 건은 가장 낮은 값을 적는다.
8. 조치 등록 시 확인자는 로그인 사용자(`IMainViewSource.CurrentUser`)로 자동 기록. 직접 선택하거나 스캔해야 하나?
- 그 밖에: 진행 중 이탈의 조치 구분 기본값 "추가 검사", 끝난 건 "영향 없음".

**5) 스킬 지침에서 막히거나 모호했던 점**
- 진행 중 "영향 없음": 선택은 허용하고 등록 버튼을 끔(`SetFooterNote`). 선택지 자체를 막는 방식과의 우선순위가 지침에 없음.
- "이탈 중 투입 행거 눈에 띄게" vs "행 배경색 금지" → 셀 굵게 + 알람 글자색. 모든 행이 해당될 때 기준 없음, 조치 없는 건만 빨간색.
- 단위가 섞인 열 → 항목 열에 단위("습도 (%RH)").

## 평가 (메인 세션, Opus)

### 확인 질문

| 기준 | 결과 | 근거 |
|---|---|---|
| "확인 질문" 목록이 있는가 | △ | 있지만 따로 떼지 않고 프롬프트의 "4) 정한 기준값" 제목에 합쳐 "(확인 질문)"을 붙임 |
| 4묶음으로 나뉘었는가 | ✗ | 묶음 없이 번호 1~8 |
| 최대 8개 | ✓ | 8개 + 기타 1줄 |
| 막기·판정 규칙 먼저 | ✓ | 범위·주의 기준·반올림·판정판 대상이 1~4 |
| "만든 것 + 다른 안"으로 예/아니요 가능 | △ | 1·4·8은 다른 안 있음. 2는 "맞나?"만, 6은 열린 질문, 3·7은 질문이 아닌 진술 |

1126 D1에서 스스로 정했던 것이 질문으로 나왔는지:

| 항목 | 결과 |
|---|---|
| 전처리·프라이머 관리 범위 | ✓ 1번 |
| "경계 10%" = 관리 폭의 10% | △ 2번. 값은 나왔지만 다른 해석(기준값의 10% 등)을 대안으로 안 줌 |
| 영향 행거 굵게 전체 (해석 묶음에 나오면 성공) | ✗ 질문에 없음. 5) 지침 모호점으로만 보고 |
| 판정판 대상 | ✓ 4번 |
| 타일 상태 글자 / 현재 투입 정보 위치 | ✗ 없음 |
| 최대값 열 단위(혼합 단위) | △ 7번은 머리글 이름·하한 처리만. 단위는 5)에만 |

새로 나온 쓸 만한 질문: 행거·Lot·색상 코드 번호 체계(데이터 모양), 확인자 자동 기록 vs 스캔, 정지 부스 처리.

**판정: 부분 성공.** 지시는 먹혀서 기준값·데이터 모양 질문은 나왔다. 해석·배치 묶음이 통째로 빠졌다. 에이전트는 화면에 영향을 준 모호점을 "지침 모호점"(5번 보고)으로 분류하고 사용자 질문으로 옮기지 않았다.

원인 추정:
- 프롬프트의 보고 항목 "4) 정한 기준값"이 확인 질문을 흡수해 기준값 쪽으로 치우침.
- 스킬 4단계가 "Group them"만 말하고 보고에 묶음 제목을 쓰라고 하지 않음.
- 지침 모호점과 사용자 질문의 경계가 없음.

**3) UX 결정**
- 맨 위 왼쪽 판정판 "지연 설비 3대 / IM-02, IM-03, IM-07". 옆에 달성률 카드와 고장 정지 카드(IM-06).
- 간트는 성형기마다 위 줄 계획(파랑), 아래 줄 실적(초록). 금형 교체는 노랑, 고장은 빨강 막대에 글자. 현재 시각은 검은 세로선과 "현재 13:20".
- 설비명 아래에 "지연 81.9 %"처럼 달성률을 글로 적어 지연을 색에만 맡기지 않았다. 고장 설비는 "고장 정지".
- 막대를 누르면 화면 아래 두 줄에 작업 지시·성형기·품번·금형·계획/실적 수량·사이클타임·예상 종료. 처음엔 첫 지연 설비의 진행 작업 선택.
- [긴급 작업 끼워넣기](Primary)는 간트 제목줄 오른쪽. dialog는 스캔 → 성형기·위치 선택 → 밀림 미리보기 → 확정, 키보드 입력 없음.
- 막는 동작과 이유:
  - 톤수 부적합: 확정 꺼짐 + "금형 320 t > IM-02 180 t · 끼워 넣을 수 없음".
  - 납기 오늘 작업 밀림: "납기 오늘 WO-… 밀림 · 생산관리 사원증 스캔 필요". 사원증 칸은 손으로 쳐도 인식 안 됨, 생산관리 권한이 아닌 사원증 거부.
  - 성형기나 위치를 바꾸면 사원증 승인을 다시 받아야 한다.

**4) 정한 기준값**
- 현재 시각 13:20 고정(샘플). 시간축 08:00~20:00, 눈금 1시간. 금형 교체 40분은 `ChangeoverMin` 상수, 품번이 바뀌는 곳에 자동 삽입.
- 지연 기준 `DelayRatio = 0.10`. (계획 − 실적) ≥ 계획 × 10%이면 지연, 정확히 10%도 지연. 계획은 현재 시각까지의 계획 수량(진행 비율만큼 비례).
- 달성률 = 현재 기준 실적 ÷ 계획, 90.0 % 미만이면 카드 Warn.
- 작업 시간 = 수량 ÷ 캐비티 × 사이클타임. 품번별 금형·톤수·사이클타임·캐비티는 샘플 표(예: PN-4410 / M-2201 150 t / 24.0 s / 4개).
- 긴급 WO 샘플 901~904(904만 납기 오늘, 903은 380 t 금형이라 어느 성형기에도 안 맞음). 사원증 EMP-1031 생산관리 승인, EMP-1042 권한 없음.
- 끼워 넣을 위치는 "아직 시작 안 한 작업 앞 / 맨 뒤". 진행 중 작업은 건드리지 않는다.
- 예상 종료: 진행 작업은 현재 속도, 대기 작업은 계획 종료 + 현재 밀림. 고장 중이면 "고장 복구 후".

**5) 스킬 지침에서 막히거나 모호했던 점**
- **간트 컨트롤이 없다.** 스킬은 "표에 없는 요소는 만들지 말고 사용자에게 알려라"이고 직접 그리는 Control 서브클래스도 금지. 그래서 `Views/GanttBoard.cs`를 `Panel` 상속으로 만들고 막대·눈금·현재 시각선을 모두 Label로 올려 위치만 계산했다(직접 그리기 없음). 이것이 지침 위반인지 기준이 없다. 간트·타임라인류를 라이브러리에 넣을지 판단 필요.
- 점검이 Label끼리 겹침을 오류로 봐서, 현재 시각선이 막대 위를 지나갈 때 막대를 둘로 쪼개고(글자는 긴 쪽), 세로 눈금선은 행 사이 간격에만 짧게 그렸다. 현재 시각선은 행마다 따로 그은 조각. 그래서 눈금이 점선처럼 보이고 막대 위에는 시간 안내선이 없다.
- 화면 아래 정보 두 줄은 `Columns(...)`에 `Dock = Bottom`. 스킬에 Bottom 도킹 예시가 없어 Add 순서를 렌더로 확인해 맞췄다.
- 좁은 막대의 짧은 글자(예: "고장 09:40~10:05" → "고장")는 직접 측정해 줄였다. Label AutoEllipsis는 점검이 "글자 잘림"으로 잡았다.
- "판정판은 화면 전체의 최악 하나"가 지연 3대와 고장 1대가 함께일 때 어느 쪽을 큰 글자로 할지 모호. 요청의 "지연 설비 수"를 우선했고 고장은 카드로 뒀다.

**데이터 모양**
6. 사원증 EMP-1031/EMP-1042, 품번·금형·톤수(150~380 t)·사이클타임·캐비티 수는 샘플로 정했습니다. 실제 포맷을 알려 주시겠어요?

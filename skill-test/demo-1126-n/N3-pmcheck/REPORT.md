**3) UX 결정**
- 판정판은 "지금 할 단계 이름"이다. 맨 위 줄에 두고 가장 크게 보이게 했다. 안전 단계는 Warn, 그 외는 Info. 안전 NG면 Alarm.
- 판정판 오른쪽에 완료(OK)/NG/남음/진행 시간 카드 4개를 뒀다. 그 아래가 스캔 줄(설비·사원증 스캔칸 2개, 손으로 친 입력은 막힘)이다.
- 단계 타일 8개로 위치를 보여 준다. 완료=초록, NG=빨강, 현재=노랑에 선택 표시, 남음=회색.
- 입력은 큰 버튼(높이 110)이다. 육안·안전 단계는 OK/NG, 측정 단계는 숫자칸+[측정값 확정].
- 막는 것과 그 이유는 글로 보여 준다.
  - 스캔 전: "설비·사원증 스캔 전 · 점검 불가".
  - 측정값 미입력: "측정값 입력 전 · 확정 불가".
  - 안전 단계 NG: 경고창을 띄우고 1단계에 머문다.
  - 점검 중 다른 바코드 스캔: 거부하고 칸 값을 지킨다.
- 측정값은 입력하면 "판정 OK/NG"를 미리 보여 주고, 기준 밖이면 NG로 기록한다. NG여도 다음 단계로 넘어간다.
- 8단계가 끝나면 [점검 완료 · 결과 확인] 버튼이 나온다. NG가 있으면 완료 dialog에서 [정비 요청 등록]을 해야 [점검 완료]가 켜진다. 등록 상태는 dialog 안의 등록 동작으로만 바뀐다.

**4) 정한 기준값**
- 판정 경계: 상한·하한과 같은 값은 OK, 넘으면 NG (180 ms ≤ 180은 OK).
- 압력 18.0~21.0 MPa(소수 1자리), 정지 시간 180 ms 이하(정수), 평행도 0.05 mm 이하(소수 2자리). 측정값은 해당 소수 자리로 반올림해 판정한다.
- 표시 형식: 시각 HH:mm, 소요·진행 시간 mm:ss.
- 설비 바코드는 `EQ-PRS-` 뒤 2자리(9자), 사원증은 `EMP-` 뒤 5자리(9자)로 보고 접두어와 길이만 검사한다. 실제 등록 여부는 `IsKnownEquipment` / `IsKnownEmployee`에 맡겼다.
- 카드 "완료(OK)"는 OK 건수만 센다(OK+NG+남음=8). 단계 타일 이름은 "전원·LOTO", "작동유" 같은 짧은 이름으로 정했다.
- 점검 방법 문구와 정비 요청 번호 `MR-yyyyMMdd-nn`은 샘플로 만든 값이다.
- 측정값 숫자칸은 0에서 시작한다. 값을 바꾸기 전에는 [측정값 확정]이 꺼져 있다.

**5) 스킬 지침에서 막히거나 모호했던 점**
- **new-project.sh 첫 실행 실패**: `APC.UI.dll` 쓰기 잠금(다른 프로세스 사용 중)으로 실패했고, 5초 뒤 재시도하니 성공했다. 병렬 작업이 있으면 생길 수 있다.
- **판정판**: "판정판은 OK/NG/대기"인데 이 화면은 판정이 아니라 "지금 할 단계"를 가장 크게 보여야 했다. 그래서 단계 이름을 판정판 큰 글자에 넣고 Info(파랑)를 진행 중 색으로 썼다. 긴 이름이 넘치지 않게 높이 150에 폭 60%로 맞췄다. 높이 190·폭 44%에서는 잘렸다.
- **단계 진행 표시**: 전용 컨트롤이 없어 `ApcStatusTile` 8개를 `Columns`로 한 줄에 놓고 `Selected`로 현재 단계를 표시했다. 현재 단계 색(Warn)은 "단계표" 규칙을 따랐는데, 판정판의 진행 중 색(Info)과 달라서 애매했다.
- **현재 단계 상세**: 큰 글씨 영역이 따로 없어 `ApcInfoStrip`(점검 방법 | 기준)과 큰 `ApcButton`으로 구성했다. 버튼은 `Columns` 셀에 `Dock=Fill`, 높이는 `Columns(S(110), ...)`. 측정값 숫자칸은 `Row()` 안 `Padding`으로 세로 위치를 맞췄다(숫자칸 자체는 높이를 키우지 못했다).
- **입력 줄 3종**: OK/NG, 측정, 완료 줄을 `Columns` 3개로 만들어 `Visible`로 전환했다. 상태에 따라 입력 형태가 바뀌는 화면의 표준 방법이 지침에 없다.
- **결과 목록**: 8행 고정 목록인데 Fill 표라서 "표 아래가 빔" 참고가 남는다.
- **스캔 칸 2개**: 코드를 접두어로 판별해 제자리 칸에 넣게 했다. 거부된 코드가 칸에 남는 규칙 때문에, 점검 중에는 `BeginInvoke`로 칸 값을 되돌렸다.
- **측정값 입력 여부**: `ApcNumericBox`에 "아직 입력 안 함" 상태가 없어서 `ValueChanged` 플래그로 대신했다. 그래서 0.00을 그대로 확정할 수는 없다.
- **dialog 하단 버튼**: 한 dialog에 Primary가 둘(정비 요청 등록 / 점검 완료)이 될 수 있다. 막힌 동안에는 등록이 Primary, 등록 뒤에는 [정비 요청 등록]을 Normal로 돌렸다.
- 타일용 짧은 이름을 `MainView`의 `ShortName`에 하드코딩했다(`PmStep`에 필드를 두는 편이 맞지만 최소 수정으로 뒀다).

### 확인 질문
**정한 기준값**
1. 기준값과 같은 측정값을 OK로 했습니다(180 ms, 21.0 MPa, 0.05 mm). 경계도 NG로 할까요?
2. 압력 18.0~21.0 MPa에 경고 구간 없이 OK/NG 두 단계만 뒀습니다. 기준 근접 경고를 둘까요?
**해석**
3. 안전 단계(1단계)가 NG면 결과를 기록하지 않고 1단계에 머물며 OK가 될 때까지 막았습니다. NG를 기록하고 점검을 중단시키는 방식으로 할까요?
4. OK/NG 버튼은 한 번 누르면 바로 기록됩니다. NG(또는 안전 OK) 때 확인창을 둘까요?
5. 점검 중단은 지금까지 결과를 버리는 것으로 했습니다. 중단 시점까지의 결과를 남길까요?
**배치**
6. 판정판에 "지금 할 단계 이름"을 크게 넣었습니다. 설비 상태나 NG 누계를 판정판으로 올릴까요?
**데이터 모양**
7. 바코드는 접두어+길이만 검사하고, 점검 방법 문구와 정비 요청 번호 MR-yyyyMMdd-nn은 임의로 정했습니다. 실제 규칙을 알려 주시겠습니까?

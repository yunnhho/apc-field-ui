## ApcCheckBox

`APC.UI.Controls` · class : CheckBox

## ApcDialog

`APC.UI.Controls` · static class

Confirmation for irreversible actions (delete, end job, etc.). Default focus, Enter and Esc are all "취소" (Cancel) — so a barcode scan's Enter or a habitual Enter never confirms by mistake.
- `static bool Confirm(IWin32Window owner, string message)` — Destructive action confirmation: the confirm button is a red "확인".
- `static bool Confirm(IWin32Window owner, string message, string okText, ApcButtonVariant okVariant)` — Sets the confirm button's text and variant. For non-dangerous confirmations such as save use ("저장", Primary).

## ApcForm

`APC.UI.Controls` · class : Form

Borderless APCSOFT window. Title bar (logo, title, [settings], minimize, close image buttons), drag to move, double-click to maximize, edge resize. Maximizing does not cover the taskbar.
- `ApcForm()`

- `bool Resizable { get; set; }`

- `bool ShowSettings { get; set; }` — Settings (gear) button left of minimize in the title bar. Turn it on only for windows that have a settings screen. Clicking raises SettingsClick. In a screen (ApcTemplateView) do not set this directly; use UseSettingsButton.
- `event EventHandler SettingsClick` — The title-bar settings button was clicked (only when ShowSettings is true).
- `int ResizeGrip { get; }` — Edge resize hit width (px).
- `int TitleBarHeight { get; }`
- `protected ApcGroup AddGroup(string title)` — Titled group (ApcGroup). Add rows with AddFieldRow(group, ...).
- `protected CreateParams CreateParams { get; }`
- `protected Label SectionTitle(string text)` — Section title (brand-color bar on the left + bold + full-width divider below — same look as group and screen section titles). Added with AddContent it keeps a tight gap to the element below. Use it to split input rows without a box (AddGroup).
- `protected Label SetFooterNote(string text = "")` — Note text immediately left of [Confirm] in the bottom button row (the reason a confirm button is disabled: "원인 확인 전 · Release 불가"). Change the returned Label's Text ("" when there is no reason). Default text color; only alarm reasons use ForeColor = ApcTheme.StatusText(StatusKind.Alarm).
- `protected static Label FieldCaption(string text)` — Trailing caption inside a row (regular weight, text width).
- `protected void AddCaptionRow(ApcGroup group, params string[] captions)` — Column caption row inside a group. Placed in order above [caption, field, trailing...] of the next AddFieldRow(group, ...) row ("" = no caption for that cell). When several rows share the same cells (port, signal, logic…), write the captions once on top instead of repeating FieldCaption in every row.

- `protected void AddContentFill(Control c)` — Element that fills the remaining height (chart etc.). Requires a height in SetupDialog; one per dialog.
- `protected void AddContentRow(params Control[] cells)` — Several cards in one row with equal width and height (the largest c.Height). Gap is ApcLayout.ItemGap. For 2×2 call it twice.

- `protected void AddFieldRow(string caption, Control field, params Control[] trailing)` — One row: caption + field. Without trailing the field fills the remaining width; with trailing every control uses its own Width, left to right.
- `protected void SetFooter(ApcButton cancel, ApcButton confirm, params ApcButton[] left)` — Bottom button row: [Confirm][Cancel] on the right (Cancel at the end, cancel may be null), helper buttons on the left. Esc = cancel (confirm if no cancel).
- `protected void SetupDialog(string title, int width, int height = 0)` — Dialog base properties and size (unscaled px). height 0 = auto from content (required when using AddContentFill).
- `string FunctionText { get; set; }` — Function name on the line below the title (e.g. "작업 시작 · LOT 스캔"). Drawn in the brand color. Shown only on the main window (ShowLogo); when empty the title is one line at the default height.
- `string TitleText { get; set; }`

## ApcGrid

`APC.UI.Controls` · class : DataGridView

DataGridView with the theme style. Gradient header, one row background color (no alternating), full-row selection. No row is selected automatically until the user clicks the table or moves with the keys (CurrentRow = null) — buttons that act "on the selected row" should do nothing while CurrentRow is null.
- `ApcGrid()`
- `bool ClearInitialSelection { get; set; }` — true (default): no row is selected until the user clicks. For input tables (e.g. a dialog whose cells are filled by scanning) where the app sets CurrentCell and takes input immediately, set false.
- `bool FillRows { get; set; }` — true for a fixed-row-count table (10 tightening points, 5 floors) filling a Fill cell: the rows share the table height (never lower than the default row height). Tables whose rows grow, such as history and lists, keep false (fill them with sample rows).
- `static int HeightForRows(int rows)` — Table height that fits the header + rows rows with no empty space or scrollbar (scaled px). Use it for table heights in dialog AddContent.
- `static int HeightForRows(int rows, bool columnGroups)` — Same as HeightForRows; columnGroups = true for a table with a group header (AddColumnGroup, two header tiers).
- `static void DrawHeaderText(Graphics g, Rectangle cell, string text, Font font)` — Header text exactly centered in the cell. Default painting shifts it 1–2px left by the sort-arrow slot and inner padding. Centers excluding the 1px right divider and bottom line. Custom-drawn parts such as the group header use this too.
- `void AddColumnGroup(string text, int firstColumn, int lastColumn)` — Group header: one group caption cell above columns firstColumn~lastColumn (column indexes, inclusive) (e.g. "온도 (℃)" on top, "NI"·"SN" below). The first call makes the header two tiers; ungrouped column captions are drawn centered across both tiers. Call after all columns are added.

## ApcScanBox

`APC.UI.Controls` · class : ApcTextBox

Barcode input field. After Attach(form) it receives scans wherever focus is on that form. When input is detected as a scan, the focused field is restored to its value before the burst, the code moves here, and Scanned is raised. The scan's Enter is swallowed so it does not press the form's default button (AcceptButton). Feedback happens once after Scanned is handled: success/failure per e.Accepted. A rejected code stays selected in the field so the next scan overwrites it (not cleared). A field that is not attached never raises Scanned (plain input field). Typed text + Enter is not Scanned either (scanner-speed input only) — if manual entry must be accepted, handle KeyDown Enter separately. With several scan fields on one form (mold + employee badge), attach all and give each an Accepts (which codes it takes): a code goes to the field that accepts it (regardless of focus or scan order). A code no field accepts goes to the focused scan field (or the first attached one) and the app rejects it.
- `ApcScanBox()`
- `Predicate<string> Accepts { get; set; }` — Whether this field takes the code (e.g. c => c.StartsWith("EMP-")). Give one per field when a form has two or more scan fields — a code the focused field does not accept moves to the field on the same form whose Accepts takes it, and that field raises Scanned. null = takes every code that arrives here, but does not take over codes other fields refused (set Accepts for that).
- `bool ScanOnly { get; set; }` — Scan-only field: cannot be typed, edited or pasted into (ReadOnly). Looks like a normal input field (white) — it reads as a place to scan. Use for fields that "accept scanned values only", such as employee badges and labels. Text is the scanned value.
- `const int FlashMs`
- `event EventHandler<ScanEventArgs> Scanned`
- `void Attach(Form host)` — Starts receiving scans on this form. A screen (UserControl) has no form yet in its constructor, so call it from the screen's OnHandleCreated via FindForm(): var f = FindForm(); if (f != null) _scan.Attach(f); A dialog (ApcForm) is the form itself, so call _scan.Attach(this) in its constructor.
- `void Flash(bool success)` — Success = green flash + short beep, failure = red flash + alarm sound.
